How the technical design becomes a document

The deliverable is a Word file rendered from confirmed JSON — the same mechanism the FS agent already runs in production, with diagrams as the one place images are generated.

Why a document generator, not image generation

A technical design is a working artefact, not a picture of one. The ABAP team copies object names out of it, QA lifts the test scenarios, the reviewer tracks changes and comments in the margin, and it goes into project document control with a version history. Rendering the corporate .docx template means the output is indistinguishable from a hand-written TD — same headers, same numbering, same fonts.

What the consultant can still change

Everything the document contains is confirmed JSON on the session, so a regenerated section, an edited table or a replaced diagram simply re-renders the file. The template itself stays under the delivery team's control — swapping in a client's own TD template is a template upload, not a code change.
